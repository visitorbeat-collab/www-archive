# WORLD WIDE WASTE — DISCOVERY AND PUZZLE SYSTEMS

**Status:** Implemented architecture / physical-release components pending final media
**Purpose:** Records intended discovery logic without converting the experience into a game checklist

---

# 1. Design Rule

Every puzzle must reward interpretation. Speed, brute force, arbitrary visit counts, and hidden-interface hunting are not valid solutions.

The desired response is:

> I understand why that became available.

Not:

> I completed enough tasks.

---

# 2. Physical Entry

The physical EP supplies the initial route through typography, lyrics, artwork, and retained audio clues. Those components are finalized with the release media and remain outside the website implementation described here.

The web archive must still make sense to a reader who receives the URL from another person, even if that reader does not experience the physical decoding process.

---

# 3. Conceptual Retrieval

The root query instrument is a narrative mechanism, not conventional full-text search. It maps human language to the Finder's current conceptual classifications and returns relationships rather than definitive answers.

Search should guide readers toward processes such as interpretation, consequence, restraint, responsibility, trustworthiness, and contact readiness.

---

# 4. Restricted Discovery

`restricted/` is absent from the initial root Index.

A query that resolves to `responsibility` reveals:

`boundary condition recognized`

and provides the restricted entrance. The state persists locally so the root navigation changes after discovery.

This does not authorize access. It reveals where the access condition exists.

---

# 5. Relational Threshold

The restricted entrance presents a radial relationship assessment. The correct arrangement expresses the archive's causal grammar rather than a memorized password.

The browser receives a signed challenge, submits its interpretation, and receives a signed restricted cookie only after server-side verification.

The gate should not celebrate success. Resolution should feel like a quiet state change.

---

# 6. Prospective Anomaly

`authority_resistance_assessment_001.html` remains reachable through the anomaly narrative but absent from normal directory and search systems.

Its unexplained provenance must not make its content more authoritative. The puzzle tests whether the reader and Finder can preserve scrutiny when a source feels unusually significant.

---

# 7. Retained-Audio Convergence

The retained-audio registry resolves only after the reader has:

- visited the five navigable restricted concepts
- observed Comparative Convergence Assessment 001

The condition represents cross-domain interpretation, not completion percentage. Audio Artifact 002 is the first concealed object in an extensible retained-audio collection.

# 8. State Reset for Testing

Public discovery:

```javascript
localStorage.removeItem("observation-index-restricted-discovered");
```

Restricted topology and retained audio:

```javascript
localStorage.removeItem("restricted-map-visited");
localStorage.removeItem("restricted-audio-convergence");
```

Restricted authorization is stored in an `HttpOnly` cookie and should be tested in a fresh private window when a complete reset is required.

---

# 9. Prohibited Failure Modes

- Do not expose the authority-resistance anomaly through search.
- Do not use local storage as authorization.
- Do not require a specific reading order for ordinary public material.
- Do not add gates whose solution is unsupported by existing evidence.
- Do not turn uncertainty into proof of external authorship.
- Do not make inaccessible media appear downloadable.
